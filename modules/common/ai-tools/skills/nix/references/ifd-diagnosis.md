# IFD Diagnosis

Import-from-derivation (IFD) builds a derivation while Nix is still evaluating.
It makes evaluation depend on a builder, slows it down, and can fail across
platforms. See the
[Nix manual on IFD](https://nix.dev/manual/nix/2.35/language/import-from-derivation)
and the [glossary entry](https://nix.dev/manual/nix/2.35/glossary#gloss-ifd).

## Calls That Can Trigger It

Each of these forces a derivation when its argument is a derivation or an
unrealized store path:

| Call | Notes |
| --- | --- |
| `import expr` | importing a generated file |
| `builtins.readFile expr` | reading generated bytes |
| `builtins.readDir expr` | listing a generated directory |
| `builtins.pathExists expr` | testing a generated path |
| `builtins.filterSource f expr` | filtering a generated tree |
| `builtins.path { path = expr; }` | copying a generated path |
| `builtins.hashFile t expr` | hashing generated bytes |
| `builtins.scopedImport x drv` | importing with a generated scope |

A static in-tree path such as `builtins.readFile ./config.json` does not trigger
IFD.

## Deny It to Find It

Turn the setting off and evaluate; a clean pass is the proof:

```bash
nix build .#package --option allow-import-from-derivation false
nix eval .#package.drvPath --option allow-import-from-derivation false
nix flake check --option allow-import-from-derivation false
```

The typical failure is:

```text
error: cannot build '/nix/store/...-source.drv' during evaluation because the
option 'allow-import-from-derivation' is disabled
```

On a cross build the same cause can surface as a builder-platform mismatch
instead of the message above.

## Locate an Obscured Sink

1. Wrap a suspected sink in `builtins.trace`; a print followed by a stall means
   the next expression is the IFD.
2. Step through with the debugger:
   `nix build .#package --show-trace --debugger --print-build-logs --verbose`.
3. Scan the expression for filesystem sinks whose target is a variable rather
   than a literal path.

## Remove It

- Make inputs explicit. A builder that reads `pname`/`version` from a fetched
  source (for example Crane reading `Cargo.toml`) can often take them as
  arguments instead.
- Do the work in Nix. Replace a `runCommand` that pipes through `gcc`, `sed`, or
  `jq` with `builtins.fromJSON`, `builtins.split`, `builtins.replaceStrings`,
  or a library string helper.
- Commit the generated file. Run the generator locally, commit its output, and
  read the static file during evaluation.
- Pin external inputs ahead of time through `flake.lock` (or `niv`/`npins`).

## Contain the Rest

Nix 2.35 does not provide parallel evaluation, so residual IFD stays on the
critical path. Keep it to the smallest expression possible, document why it is
unavoidable, and measure the cost before and after
(see [Evaluation cost](evaluation-cost.md)).

## Confirm the Removal

- `--option allow-import-from-derivation false` completes.
- Evaluation time was re-measured (see [Evaluation cost](evaluation-cost.md)).
- No builder step runs during the evaluation phase.
